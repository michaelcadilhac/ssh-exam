## Required state review before any broad qualification

1. Legacy active/prepared attempts keep absent owner metadata; no backfill or
   silent conversion to retained mode. Explicit new bindings apply only after
   positively scoped Begin/continuation. Trusted administrator sandbox exceptions
   must preserve their existing supported path; the monitor contract UID is>=1000.
2. Page/epoch mismatch in fresh Begin refuses before grant/clock consumption.
   Lost replies/restart reuse the original Begin intent and preserve saved work;
   a second page cannot create a replacement interval or claim existing input.
3. Persist registered owner with the authoritative actual start, never before as
   execution permission. Generate entropy before irreversible one-use publication.
   Inspection is diagnostic; no arbiter seal or permission is restored from disk.
4. Capabilities carry the exact comparable owner value. Check it again at real
   closed release, alongside current peer, account, lease/deadline and incarnation.
   Another page, root transport, generation or clock context rejects stale work.
5. Lock/auth loss/expiry/finalization preserve identifiers for history, not work.
   Authorized continuation replaces ownership only after current approval, peer,
   readiness and deadline checks; stale completion cannot undo a newer incident.
6. Clock changes require current metadata and later live-authority handover.
   Copy owner values when changing them: shallow pointer mutation would invalidate
   the existing immutable pane snapshot comparison. Benign receipt ACKs must not
   rotate ownership or block final release. No unrelated pane/attempt may stop.
7. Supervisor accepts only positively rooted matching cohorts. Registering identity
   is not arming C10. Root caller death, stale handshake, live old panes, late close,
   unconfirmed cleanup and restart need explicit refusal/inspection behavior.
8. Signed callbacks/receipts preserve historical owner metadata after page logout;
   page mismatch must not reject a legitimate protected-completion callback.
   Apply current-page checks to positive admission, not negative safety cleanup.

## Integrated implementation and completed state review

Migration029 adds nullable Begin-intent owner_page and attempt registered_owner;
there is no historical backfill, account reservation, permission or new interval.
The original intent retains its registration mode across uncertain replies: an
old null page stays legacy, while a declared page must match both the current
gateway page and the authenticated outbound C15 verification/echo. Native entropy
and structural checks precede start publication. Contradictory owner metadata on
an unstarted preparation refuses before clock commitment. Actual start saves the
identity with its original interval; exact retries after Engine restart preserve
both. Cancellation/expiry continue their existing positively confirmed cleanup.

Production uses an isolated connection worker, not the in-process browser class.
The worker has no Store. Bounded parent-authority IPC now obtains each canonical
signed command and current pane check from the owning gateway; SSH/terminal work
stays isolated. At most64 authority requests per worker, each with a five-second
bound; a late reply cannot create a clock, reservation or restored permission.
Account scope is checked independently. Parent loss ends the worker through the
existing disconnect handling. A refusal is recoverable and affects no sibling.
This is not the future native live-authority loop and does not issue C10 permits.

Registered capabilities carry an exact comparable owner value. Real closed launch
rechecks that value and immutable attempt authority; changed page/epoch, erased
owner or contradictory capability refuses before student code. Existing SSH
peer/account/lease/deadline checks remain. Versioned positive issue/renew/consume
purposes refuse old agents; strict supervisor decoding rejects unknown registered
handoffs in older loaded owners. New code never implicitly converts a legacy
attempt. Current-root, per-pane input and loaded-role qualification remain needed
before any retained-mode enablement.

The existing one supervisor accepts only a matching rooted timed cohort. A new
page/authorization epoch cannot join old live timed panes. Clock-only updates are
monotonic; owner changes copy values, preserving captured immutable snapshots.
Continuation rotates the authorization epoch only after existing approval, fresh
registration/readiness and original-deadline checks. Old lease journals cannot
renew another page/epoch/clock context. Lock, expiry and protected completion keep
identity as history, never execution permission. Signed late callbacks cannot
roll metadata back; completion remains accepted after page logout. Pane receipt
checks use the current gateway page; refusal sends only that browser channel a
best-effort close, without claiming verified native cleanup or closing siblings.

Supported inspection: examctl info ATTEMPT --read-only, list --read-only and
panes supervisor ATTEMPT [--state DIR]. Optional registered_owner is diagnostic
metadata, also carried by web attempt responses. Lease matches_recorded_owner

operators to compare status and use the same authorized page/approved continuation;
never edit saved ownership, clear the original intent or reset a clock to retry.
