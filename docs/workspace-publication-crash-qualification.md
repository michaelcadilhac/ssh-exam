# Saved-work publication crash qualification — local increment

October22,2026. In progress, not deployed and not a completed recovery/unified-
grant investigation. No production process, student record or service is touched.
This closes specific process-death coverage gaps; it does not enable C3 retained
SSH, automatic clock refunds, completed-attempt reopening or new live grants.

## Scope and acceptance

Use the public native prepare/Begin/Admin repair/retry workflows and actual
SIGKILL of disposable test children at these boundaries:

| Boundary | Durable result required after child death |
| --- | --- |
| Private copy complete, before publication | No clock/consumption; retry from the verified protected source |
| Private ready tree published, before adoption | No clock/consumption; adopt the existing receipt without inventing time |
| Original start/hold durably committed | Preserve exact interval even before a consumption marker exists; no fresh attempt reuse |
| Recovery consumption durably recorded | Marker names only the original attempt; no second grant consumption |
| Work rename/directories flushed | Preserve published inode and any retained edits; never recopy source over it |
| Initialized marker/directories flushed | Restart/repair cannot reset time, reopen execution or lose saved bytes |

The four post-start fault points extend the existing private, non-configurable
workspaceCheckpoint test seam. Production has no config/environment mode to
activate these callbacks, and nil checkpoints preserve runtime behavior. Initial
tests correctly showed these four death points were not reachable through the
old seam; that is a missing qualification hook, NOT evidence of an old product
defect. The two existing pre-start checkpoints already passed actual child death.

Exercise both operator-first and native Tick/watchdog-first order after restart.
Unpublished work must fail collection safely, retain the original interval/hold
and remain explicitly repairable. Already published work may be protected by the
watchdog directly; then completed-attempt repair must refuse. Successful repair
leaves COLLECTION_FAILED with zero execution lease/continuation permission until
explicit protection, never ACTIVE. An idempotent Begin retry can return the
original failed result: a successful response is not reopened execution.

Require unchanged source archive AND manifest bytes, protected source identity/
interval/hold, exact new protected answer hash, original consumption/clock fences,
retained published edits and healthy independent signed peer renewals. Public
receipts must continue redacting owner transport and live lease; check their
private state/journal separately, never weaken DTO privacy for a test.

The namespace-root leg builds and runs the actual static examctl workspace-repair
CLI, including completed-result refusal. It does not run a real-root collector or
kill host UID processes. All fresh synthetic Engines explicitly mock OS/account
admission, writer termination/quiescence and cutoff. Native Tick executes its real
state/collection control flow, but this is NOT privileged SSH/PAM/cgroup/watchdog
daemon proof. Ordinary root CLI configuration validation remains enabled.
